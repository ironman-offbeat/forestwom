# Forestwom 화면 개편 및 Google Drive 저장 기능 작업계획서

작성일: 2026-11-25 (대한민국 표준시)

대상 저장소: https://github.com/ironman-offbeat/forestwom

기준 구현: `0c5713c` — 기존 화면·PDF 처리·검산 코드 확인. 해당 커밋의 GitHub 자동 검증·배포 성공 확인.

문서 상태: **작업계획 작성. 아래 화면 변경과 Google Drive 연결·저장 기능은 아직 구현하지 않음.**

## 1. 변경 목표

1. 화면과 출력물에서 ‘실사용 금지’, ‘실험용으로만 사용’, ‘가상·비식별 자료 전용’과 같은 사용 제한 문구 및 해당 확인 체크박스를 제거한다.
2. 상단의 큰 홍보 문구를 없애고 실제 작업 순서를 간단히 안내한다.
3. 사용자가 등록한 PDF와 검토 결과를 본인의 Google Drive에 함께 저장한다.
4. 저장된 건을 다시 열어 원본 도면과 검토값을 확인하고 이어서 작업할 수 있게 한다.

사용자의 2026-11-25 지시에 따라 기존 계획의 ‘외부 저장 없음’ 정책을 ‘사용자가 저장 버튼을 누르면 연결한 Google Drive에 저장’으로 변경한다. 기존 작업계획서는 초기 구현 이력으로 보존하고, 이번 변경의 범위·화면 정책은 이 문서를 따른다.

## 2. 화면 및 문구 변경

### 상단 안내 영역

기존 ‘도면에서 근거까지, 확인하며 검토합니다.’ 제목과 설명을 삭제한다. 공간을 줄이고 다음 세 단계와 작업 버튼을 배치한다.

**PDF를 넣고, 확인한 결과를 저장하세요.**

| 단계 | 표시 문구 | 연결 동작 |
| --- | --- | --- |
| 1. 도면 등록 | 신청서와 도면 PDF를 넣으세요. 페이지별 원본과 수치 후보가 표시됩니다. | PDF 선택 영역으로 이동 |
| 2. 수치 확인 | 추출된 수치를 원본과 비교하고, 필요한 값을 수정한 뒤 확정하세요. | 원본 대조 영역으로 이동 |
| 3. 결과 검토·저장 | 검산 결과와 보완사항을 확인하세요. 검토 의견서를 출력하거나 도면과 함께 Drive에 저장할 수 있습니다. | 의견서 영역 및 Drive 저장 |

현재 페이지 수·확정 수치 수는 작은 진행 표시로 유지한다. 실제 클릭 동작이 없는 안내를 실행 버튼처럼 표시하지 않는다.

### 문구 정리 범위

| 위치 | 변경 내용 |

| 의견서 | ‘실험용’, ‘가상·비식별 전용’ 문구 제거. 제목은 ‘건축협의 조경 검토 의견서’ |

‘판독 보류’, ‘원본 확인 필요’, ‘기준 미달’, ‘담당자 검토 전’, 누락된 출처 등은 결과의 정확성을 나타내므로 유지한다. 문구 변경을 근거로 검산 범위를 확대하거나 미확인 결과를 승인 완료로 바꾸지 않는다. 실제로 확보되지 않은 기존 자료·정오표도 확인 완료로 처리하지 않는다.

## 3. Google Drive 연결

### 사용자 흐름

1. 첫 사용 시 **Google Drive 연결**을 누른다.
2. 저장할 Google 계정으로 로그인하고 파일 접근을 허용한다.
3. 연결된 계정과 저장 폴더를 화면에서 확인한다.
4. 이후 **Google Drive에 저장**을 누르면 같은 계정의 `Forestwom` 폴더에 저장한다.
5. 저장 완료 후 **Drive에서 열기**와 **저장된 검토 열기**를 제공한다.

새 Google 계정을 만드는 방식이 아니라 사용자의 기존 계정에 전용 폴더 하나를 만든다. 새로고침이나 접근 토큰 만료 시 필요한 경우 재연결한다. 자동으로 다른 계정에 저장하지 않는다.

### 연결 구현

- GitHub Pages 정적 웹앱을 유지하고, Google Identity Services와 Google Drive API를 사용한다.
- Google Cloud 프로젝트에서 Drive API, OAuth 동의 화면과 웹 클라이언트 ID를 설정한다. 배포 도메인과 개발용 주소를 허용 출처로 등록한다.
- 전체 Drive 접근 대신 `drive.file` 범위로 앱에서 생성하거나 사용자가 앱에 허용한 파일만 다룬다.
- 기본 폴더는 웹앱 로그인 후 앱이 직접 생성한다. 같은 이름만 보고 기존 폴더를 임의 선택하지 않고, 앱 표식과 폴더 ID로 재사용한다.
- 이 대화에 연결된 Google Drive 도구의 권한은 공개 웹앱에 자동 승계되지 않는다. 웹앱용 OAuth 연결을 별도로 구성해야 한다.
- 브라우저에서 사용자 Drive로 직접 전송한다. GAS, 유료 AI API, 중계 저장 서버는 추가하지 않는다.
- 클라이언트 시크릿이나 서비스 계정 비밀키를 웹앱·GitHub에 넣지 않는다. 접근 토큰은 메모리에 두고 만료 시 재연결한다.
- Drive 연결 전에는 Google 인증 라이브러리를 불러올 필요가 없도록 분리한다. 연결 후 필요한 Google 인증·API 주소만 콘텐츠 보안 정책에 추가한다.
- 계정 변경 시 기존 계정의 폴더 ID와 파일 목록을 분리한다. 연결 해제는 저장된 Drive 파일을 삭제하지 않는다.

**구현 시 필요한 사용자 동작:** 최초 Google 계정 선택·로그인·권한 허용. 개발자가 앱 코드만으로 대신 승인할 수 없는 단계다. 현재 이 웹앱의 OAuth 설정이나 계정 연결이 완료되었다고 가정하지 않는다.

## 4. 저장 버튼과 저장 단위

버튼명은 GitHub 코드 저장과 혼동되지 않도록 **Google Drive에 저장**으로 한다. 상단과 의견서 하단에서 같은 저장 기능을 실행한다.

저장 창에는 다음 항목을 표시한다.

- 검토 건 이름: 최초 등록 PDF의 확장자를 뺀 이름을 기본값으로 사용하며 수정 가능.
- 저장 위치: 연결 계정의 `Forestwom` 폴더.
- 포함 항목: 원본 PDF 목록, 검토 의견서 PDF, 이어서 검토하기 위한 데이터.
- 검토 상태: 작성 중 / 확인 필요 / 담당자 검토 기록 있음.
- 저장 버튼 및 진행률, 완료된 파일 수, 오류·재시도 안내.

수치 확정이 끝나지 않아도 작성 중 상태로 저장할 수 있다. 저장 완료는 법령 검토 또는 담당자 승인 완료와 별도로 표시한다. 저장을 시작한 시점의 원본·수치·의견·이력을 하나의 스냅샷으로 묶는다. 저장 도중 편집 내용이 바뀌면 새 변경사항이 남아 있음을 표시한다.

## 5. 폴더 및 파일명

날짜는 **저장 시점의 한국 날짜 `YYYY-MM-DD`**를 사용한다.

```text
내 드라이브/
└─ Forestwom/
   └─ [2026-11-25] 조경계획도/
      └─ v001/
         ├─ [2026-11-25] 조경계획도.pdf
         ├─ [2026-11-25] 건축허가신청서.pdf
         ├─ [2026-11-25] 조경계획도_검토의견서.pdf
         └─ [2026-11-25] 조경계획도_검토데이터.json
```

- 여러 PDF는 검토 건 하나로 묶는다. 서로 다른 원본은 각 파일의 원래 이름을 살린다.
- 같은 검토를 수정해 다시 저장하면 `v002`, `v003`으로 보존하고 이전 버전을 덮어쓰지 않는다.
- 검토 건 폴더의 날짜는 최초 저장일, 각 버전 안의 파일 날짜는 해당 버전 저장일로 한다.
- 같은 날 같은 이름의 새 검토는 폴더명에 `(2)`, `(3)`을 붙여 구분한다. 실제 연결은 표시 이름이 아닌 내부 검토 ID·Drive 파일 ID로 관리한다.
- 원본 이름 중복도 번호로 구분하고, 검토 데이터에 원래 파일명을 별도로 보존한다.

## 6. 저장 내용과 다시 열기

| 저장 대상 | 포함 내용 |
| --- | --- |
| 원본 PDF | 등록한 파일 원본 바이트. 파일명, 크기, 해시, 내부 문서 ID로 식별 |
| 검토 의견서 PDF | 핵심 수치, 출처 페이지, 계산식·적용 근거, 보완사항, 검토 메모, 담당자 기록, 확정 이력 |
| 검토 데이터 JSON | 형식 버전, 검토 ID, 저장일시, 문서·페이지 참조, 후보·확정값, 사유, 적용 법령 버전·확인일, 메모, 이력, Drive 파일 ID 및 저장 완료 상태 |

현재 `window.print()`는 사용자가 인쇄하는 기능으로, 앱이 출력 PDF 바이트를 자동으로 받는 기능은 아니다. Drive 업로드용 의견서는 별도 PDF 생성 기능을 구현한다. 화면과 PDF가 같은 검토 데이터 모델을 사용하도록 하고 한글 글꼴, 줄바꿈, 표, 페이지 나눔을 검증한다. 브라우저 내 PDF 생성과 배포 가능한 한글 글꼴을 사용한다.

현재 PDF 처리 모델에는 원본 `File`이 남지 않으므로 이를 메모리에 별도로 보존하도록 수정한다. PDF.js worker로 전달된 배열을 재활용하지 않고 원본 파일에서 저장용 데이터를 얻는다.

**저장된 검토 열기**에서는 건 이름·저장일·최근 버전·검토 상태를 보여준다. 선택한 건의 원본 PDF와 데이터를 읽어 화면을 복원한다. 임시 페이지 ID를 새로 만든 문서와 잘못 연결하지 않도록 영속 문서 ID와 페이지 번호로 매핑한다.

저장 당시 결과·담당자 기록은 이력으로 보존한다. 법령 확인일 만료, 규칙 버전 변경, 수치 수정이 있으면 현재 검토에서는 재확인 필요로 표시한다. 버전 형식이 지원되지 않거나 파일이 누락된 경우 임의로 복원하지 않고 해당 항목을 알린다.

## 7. 저장 안정성

- 큰 PDF는 재개 가능한 업로드를 사용하고 파일별 진행률을 표시한다.
- 저장 버튼 중복 클릭을 막고, 같은 저장 요청의 재시도는 완료된 파일을 중복 생성하지 않도록 요청 ID로 관리한다.
- 일부 파일만 올라간 상태는 ‘저장 완료’로 표시하지 않는다. 마지막에 완료 목록과 검토 데이터를 기록하고 재조회하여 확인한다.
- 재시도는 실패한 파일을 대상으로 수행한다. 탭을 닫은 뒤의 복구는 Drive의 저장 중 버전과 다시 선택한 원본 해시를 대조한다.
- 권한 거부, 인증 만료, 용량 부족, 네트워크 단절은 원인을 구분해 표시한다.
- 저장 전 자료는 메모리에 유지한다. 문서·결과·토큰을 브라우저 영구 저장소에 자동 보관하지 않는다.
- 기본 폴더·파일을 공개 공유로 변경하지 않는다. 화면에서 연결 계정과 저장 위치를 확인할 수 있게 한다.

## 9. 검증 항목

- 사용 제한 문구 제거와 등록 전 체크박스 제거, 키보드 접근·모바일 화면 확인.
- Google 미연결·로그인 취소·만료·재연결·계정 변경.
- 한국 시간 자정 전후 `[날짜]` 이름, 여러 PDF·동일 이름·같은 날 재저장.
- 저장 후 Drive 파일 수·종류·원본 해시 확인 및 실제 Drive 링크 열기.
- 일부 실패·통신 단절·중복 클릭 시 잘못된 완료 표시나 파일 중복 방지.
- 의견서 PDF 한글·표·출처·미확정 상태·담당자 기록 시각 검증.
- 새로고침 뒤 검토 복원, 문서/페이지 매핑, 규칙 버전·법령 최신성 재확인.
- 기존 36개 규칙 테스트 유지. 기존 9개 브라우저 테스트는 제거된 문구·변경된 저장 동작에 맞춰 조정하고 저장 시나리오 추가.
- 저장 버튼 전 PDF 데이터 전송 없음, 저장 후 지정 Google API에만 전송, 토큰·파일 본문이 로그·GitHub에 포함되지 않음.

실제 연결 검증용 파일은 별도 이름의 샘플로 생성하고, 완료 보고에 저장 위치와 파일 링크를 남긴다. 자동 테스트의 모의 Drive 응답 통과를 실제 계정 저장 성공으로 보고하지 않는다.

## 10. 산출물 및 설정 전제

- 개편된 웹앱과 Google Drive 저장·다시 열기 기능.
- Google 연결 설정 안내, 저장 데이터 형식 설명, 테스트 결과.
- GitHub 커밋과 배포 주소, 실제 저장 확인 링크.

필요한 연결 설정은 Google Cloud 프로젝트·Drive API·OAuth 웹 클라이언트·동의 화면·허용 출처·사용 계정이다. 기존 설정 유무를 구현 단계에서 확인하고 부족한 설정만 준비한다. 계정의 조직 정책이나 앱 검증 요건에 따라 추가 설정이 필요할 수 있다. 유료 AI·GAS는 도입하지 않으며 저장 공간은 연결 계정의 Drive 용량을 사용한다.
