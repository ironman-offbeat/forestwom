# 접수와 결과 공개 운영

- 입력: `https://forestwom.2hayoung.com/`
- 결과: `/#/result/접수번호` (입력 화면에서 발급)
- 관리자: `/#/admin`
- 기존 원본 대조·검산: `/#/review`

이용자는 PDF를 선택하고 검토 요청을 누른다. 서버가 원본 길이·SHA-256·PDF 헤더를 검증한 뒤 접수한다. 담당자는 관리자 화면에서 원본 PDF와 분석 요청문·JSON 템플릿을 다운로드하여 ChatGPT에 첨부한다. AI 분석 API는 호출하지 않는다. 접수 페이지는 OCR이나 AI 분석 완료를 주장하지 않는다.

result.json을 가져오면 미리보기가 열린다. 화면과 PDF는 동일한 결과 데이터에서 앱이 생성한다. JSON은 접수번호·원본 이름/해시가 일치해야 한다. 확인 판정에는 원본 근거 페이지가 필요하다. 공개 시 원본을 다시 해시 검증하고 법령 확인일(최근 30일 이내)·기록·담당자 확인을 검사한다. 서명된 기록이 변조되면 읽기를 거부하며 결과 PDF 다운로드도 해시를 검증한다. 근거 내용의 진실성과 적용 법령은 담당자가 대조해야 한다.

## 검토자 접근 분리 (2026-11-28 개선)

이전 공개 관리자 방식은 폐기했다. 신규 Slack 알림은 7일 유효한 서명 전용 링크를 포함한다. 앱에서 이를 교환하면 HttpOnly·Secure·SameSite=Strict 쿠키로 12시간 검토 권한을 부여한다. ADMIN_KEY는 서버 내부 서명값으로 그대로 유지하며 브라우저에 노출하지 않는다. 제출자는 결과 링크로 진행 상태·공개 결과·보완 제출만 이용한다. 관리자 API와 기존 저장소 API는 검토 권한이 필요하다.

과거 일반 Slack 관리자 링크만으로는 권한을 얻을 수 없다. 새 접수의 전용 링크로 접속하면 기존 접수도 목록에서 검토할 수 있다. 링크 소지자는 전체 접수 검토 권한을 가지므로 담당자 외 공유하지 않는다. 인증 방식 변경 외에 알림 대상·완료 알림·자동 재전송은 변경하지 않는다.

## Slack 최초 연결

채팅에 설치된 Slack 도구는 배포 웹앱의 인증이 아니다. Vercel 팀 261에서 Slack 커넥터를 생성하고 Forestwom 운영 환경에 연결한 뒤, 반환된 UID를 `SLACK_CONNECTOR` 환경 변수에 저장하고 재배포한다. OAuth/워크스페이스 설치 승인은 소유자가 직접 수행한다. 커넥터 생성이 지원되지 않는 경우 전용 Slack 앱에 `chat:write` 권한을 부여하고 Bot Token을 `SLACK_BOT_TOKEN` Secret에 등록할 수 있다. 둘 다 설정되면 Connect를 우선한다.

알림 대상은 확인된 소유자 Slack ID `U0AF5B880F3`으로 서버에 고정했다. [Slack chat.postMessage 공식 문서](https://docs.slack.dev/reference/methods/chat.postMessage/)의 사용자 ID 대상 전송 방식을 사용한다. PDF 내용은 보내지 않고 도면명·접수번호·관리자/Drive 링크만 보낸다. 원본 저장과 접수 상태 저장이 끝난 뒤에만 발송한다. 실패·미연결 시 접수는 유지하고 관리자 화면의 재전송 버튼을 사용한다. 전송 완료 요청은 다시 보내지 않는다. 자동 무한 재시도나 별도 스케줄러는 두지 않았다.

## 제한 및 복구

- 업로드 실패 후 같은 화면에서 재시도하면 완료된 파일을 건너뛴다. 접수번호를 보관하면 완료 여부를 확인할 수 있다. 새로고침하면 업로드 세션은 잃으며 미완료 폴더는 관리자가 Drive에서 확인한다.
- 단일 소유자 운영용이다. 같은 접수에 동시에 여러 관리자 탭에서 공개/상태 변경을 하지 않는다. Drive에는 데이터베이스 수준 트랜잭션이 없다.
- Slack 전송 후 상태 저장 실패/동시 재전송 시 중복 알림 가능성이 있다. 동일 client_msg_id를 전달하지만 정확히 한 번 발송을 보장하지 않는다.
- 접수는 익명이며 별도의 영구 요청 제한 저장소를 구성하지 않았다. 대량 남용 방지는 호스팅 방화벽 등 운영 설정이 필요하다.
- 공유 Drive 편집자는 원본·메타데이터를 삭제할 수 있다. 서명은 변조 감지이며 삭제나 데이터 공개를 막지 않는다.
- 관리자 접수 목록과 변경 기능은 로그인 없이 공개되어 있다. 결과 링크 이용자는 해당 접수의 공개 결과·보완 요청·제출 이력을 확인한다. Drive 폴더 공유 권한은 기존 사용자 설정을 따른다.
- 운영 접수·관리자는 Vercel에서 동작한다. GitHub Pages 진입은 운영 앱으로 연결한다. 로컬 Vite는 UI/검산만 제공하며 API 통합은 운영 또는 별도 로컬 API 서버가 필요하다.

## 운영 연결 확인 — 2026-11-27

Slack 커넥터 slack/forestwom을 OFFBEAT 워크스페이스에 설치하고 Forestwom production에 연결했다. 운영 가상 요청을 통한 소유자 DM 알림 수신을 확인했다. 위 최초 연결 안내는 재설정 시 참고 절차다. 관리 화면은 최신 Slack 전용 링크에서 접속한다. 로컬 .env.admin은 서버 서명 키 보관용으로만 유지하며 Git에서 제외한다.

현재 Hobby 연결 화면에는 30일 동안 토큰 요청 500회, 트리거 전달 1,000회가 포함되고 한도 도달 시 중지된다고 표시되었다. 유료 업그레이드는 하지 않았다. 한도로 알림이 실패하면 접수는 유지되며 관리자에서 확인한다.

## 접수별 검토·보완·생성 결과 — 2026-11-28 기능 브랜치

1. 접수 상세에서 **사건 검토표 열기**로 원본·사건 정보·수치를 대조하고 저장한다.
2. 항목별 법령·조항·시행일·원문 확인일·적용 사유·도면 근거를 기록한다. 판정은 수치 확인 상태와 별개이며 자료나 조건 변경 시 다시 확인한다.
3. 자료가 부족하면 접수 상세에서 구체적인 보완 요청을 게시한다. 최종 결과 공개 게이트와 분리되어 있어 법령 미확인 상태에서도 요청할 수 있다.
4. 이용자는 같은 결과 링크에서 PDF를 추가 제출한다. 최초 원본을 덮어쓰지 않는다. 제출 후 사건·수치·법령 확인 및 판정을 다시 받으며, 담당자는 기존·수정본을 대조한다. 보완 요청을 잘못 게시했으면 사유를 남겨 취소한다.
5. 저장된 검토표에서 생성한 결과 화면과 PDF를 대조하고 공개한다. 자동 생성 경로에서는 동일한 데이터로 PDF·JSON을 만든다. ChatGPT JSON 가져오기 경로도 앱에서 PDF를 생성한다.
6. 자료가 추가된 뒤 이전 결과가 있으면 원래 원본에 대한 결과로 유지하고 이전 결과임을 표시한다. 새 원본이나 검토표 변경 전 만들어 둔 공개 세션은 다시 준비한다.

보완 요청은 접수별 최대 20차·회당 10개 항목, 법규 검토 항목은 최대 30개다. 전체 원본 제한은 추가 제출분을 포함해 10개·100MB다. 최종 결과에는 자동 검토 범위와 미검토 사항을 남긴다. 현재는 성남시 일반 건축물 조경 면적 검산과 담당자의 수동 법령 검토 기록이며 건축 도면 전체 자동 판정 기능이 아니다.

운영 반영 전 별도 미리보기 환경에서 Drive 쓰기·조건부 저장·대용량 원본·Slack 보완 알림을 검증해야 한다. 이 개발 과정에서는 실제 운영 자료를 생성·변경하지 않았다.
