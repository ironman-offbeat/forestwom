# 접수·수동 AI 분석·결과 공개 — 2026-11-26

1. `/`는 PDF 접수, `/#/result/접수번호`는 진행 상태와 공개 결과, `/#/admin`은 관리자 작업 화면으로 구분한다. 기존 검산 도구는 `/#/review`로 유지한다.
2. 이용자는 이름·PDF·요청 메모만 입력한다. 원본 업로드가 완료된 후 접수번호와 결과 링크를 제공한다. PDF.js 추출은 브라우저에서 하며 스캔본은 분석 담당자가 원본을 확인한다.
3. Drive 전용 폴더에 날짜·도면명으로 접수 폴더를 만든다. 업로드 완료 전에는 접수·알림을 완료 처리하지 않는다. 재시도는 같은 업로드 세션을 사용한다.
4. 서버 서명으로 접수·결과 메타데이터 변조를 감지한다. 관리자는 별도 비밀키로 로그인하며 키는 서버 Secret, 세션은 HttpOnly 쿠키로 관리한다.
5. 관리자 화면에서 원본 다운로드, 분석 요청문·JSON 템플릿 다운로드, 분석 중 상태 설정, 결과 PDF·JSON 검증/미리보기/공개를 제공한다. JSON은 접수번호·원본 해시·근거 페이지를 검증한다. 이전 결과 버전은 보존한다.
6. 접수 완료 후 소유자 Slack으로 알림을 전송한다. 실패하면 접수는 보존하고 관리자에게 실패 상태와 재전송 버튼을 제공한다. 배포 앱의 Slack 연결은 채팅 커넥터와 별개다.
7. GAS·유료 AI API를 사용하지 않는다. AI 분석은 소유자가 이 채팅에서 수행한다. 앱이 자동으로 AI 분석을 했다고 표시하지 않는다.
8. 서버 권한/변조/업로드 실패/결과 매칭/Slack 실패 테스트와 화면별 브라우저 테스트를 수행한다. 운영 Drive 왕복과 실제 Slack 연결 검증은 모의 테스트와 구분해 기록한다.
9. 코드·계획·검증 기록을 GitHub에 반영하고 Vercel 운영 배포를 확인한다. Slack 설치 승인이 필요한 경우 설정 화면까지 준비하여 사용자에게 넘긴다.

## 운영 한계

Drive 공개 편집은 사용자의 기존 선택을 유지한다. 공개 편집자는 원본을 바꾸거나 지울 수 있으며 앱은 해시/서명 불일치를 거부한다. 로그인 없는 접수는 링크 보유자가 이용할 수 있다. 관리자 비밀키는 강한 임의값으로 생성하고 공개 번들·URL·Git에 넣지 않는다. 알림 전송 후 기록 갱신이 실패하는 드문 경우 재전송 알림이 중복될 수 있다.
